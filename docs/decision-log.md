# ReqVerify Architecture & Research Decision Log

This log records all foundational architectural, empirical, and statistical decisions made during the design and development of ReqVerify, including rationale and empirical evidence.

| Decision ID | Date | Status | Summary of Decision | Academic / Technical Rationale | Evidence / Source |
|---|---|---|---|---|---|
| **D1** | 2026-10-18 | Locked | Pin model `claude-sonnet-5-5`; strict parameter discipline (omit temperature, top_p, top_k, prefill, tool_choice, disabled thinking) | Claude Sonnet 3.5 deprecation; Sonnet 5.5 is current. Passing disallowed sampling params returns HTTP 400. | Official Anthropic API documentation & migration guide. |
| **D2** | 2026-10-18 | Locked | Playwright Python only; replace removed `page.accessibility` with `page.aria_snapshot()`; role+name locators | `page.accessibility` was permanently removed in Playwright 1.57. ARIA snapshots provide resilient semantic accessibility trees. | Playwright Python v1.59+ API specifications. |
| **D3** | 2026-10-18 | Locked | Four canonical execution statuses: `PASS`, `FAIL`, `ERROR`, `UNTESTED` with mandatory `untested_reason` | Eliminates ambiguity between test assertion failure (app defect) and script/locator failure (runtime crash). | Guide §7.3; Senior Lecturer Defense Guide. |
| **D4** | 2026-10-18 | Locked | Deterministic SHA-256 condition IDs generated in code via `make_condition_id(req_id, source_span, ordinal)` | Prevents ID churn across LLM extractions and provides stable tracking for condition-level bootstrap sampling. | Guide §7.1; NFR-06. |
| **D5** | 2026-10-18 | Locked | Unique UUIDv4 `run_id` prefixing all log files, SQLite checkpointer threads, cache keys, reports, and traces | Ensures complete audit trail and guarantees independence between replicate evaluation runs. | Guide §3, §6.3; Run Manifest Specification. |
| **D6** | 2026-10-18 | Locked | Mutant registry (`techstore/mutants/registry.yaml`) strictly isolated and unreachable by agent pipeline | Prevents data leakage and ensures benchmark objectivity; agents verify against requirements and live DOM only. | Empirical SE evaluation standards (Baltes & Ralph, 2022). |
| **D7** | 2026-10-18 | Locked | Test assertions derived from `predicate_text` are immutable across all critic repair iterations | Prevents the generator or critic from weakening assertions to artificially pass tests (self-correction pathology). | Huang et al. (ICLR 2024); Guide §3. |
| **D8** | 2026-10-18 | Locked | Agent 3 implemented as isolated LangGraph subgraph invoked per condition with iteration counter capped at 3 | Fitting all conditions into one graph exceeds LangGraph recursion limits (25 steps); capping iterations prevents infinite loops. | Guide §10; NFR-03. |
| **D9** | 2026-10-18 | Locked | Runtime token and cost budget guard enforcing early abort on threshold breach | Protects researcher from runaway API costs during multi-replicate benchmark execution. | Guide §6.1, §16.3. |
| **D10(a)**| 2026-10-18 | Locked | Zero-shot LLM baseline evaluated on identical SUT variants and replicate counts | Required baseline to demonstrate value added by multi-agent decomposition over single-prompt prompting. | Research Question RQ4; Guide §11.1. |
| **D10(b)**| 2026-10-18 | Locked | WebTestPilot comparative baseline evaluated as optional stretch pending licensing and feasibility audit | Comparative baseline against state-of-the-art literature (Teoh et al., FSE 2026). | Teoh et al., arXiv:2602.11724; Guide §16.4. |
| **D11** | 2026-10-18 | Locked | Primary evaluation protocol is Protocol P-B (separate Docker container per mutant); Protocol P-A secondary | Prevents state corruption across mutant evaluations and mirrors production containerized verification. | Guide §1 Item 12; Senior Lecturer Defense Guide. |
| **D12** | 2026-10-18 | Locked | Pre-registration analysis plan `eval/analysis_plan.md` frozen and committed to git prior to benchmark runs | Enforces scientific rigor, prevents post-hoc metric hacking, and satisfies dissertation examiners. | Runeson & Höst (2009) guidelines; Guide §14. |
| **D13** | 2026-10-18 | Locked | Prompts and thresholds tuned exclusively on `dev_app` development set, never on TechStore evaluation set | Prevents overfitting and maintains strict separation between train/tuning data and test evaluation data. | Guide §1 Item 13, §8.1. |
| **D14** | 2026-10-19 | Implemented | Ground truth dataset formalization (`requirements.md`, `conditions.csv`, `mutants_expected.csv`) with 100% verbatim source spans and backend-only `REQ-09` (`ui_observable=False`, `expected_clean=UNTESTED`) | Provides unambiguous evaluation oracle and benchmark ground truth answer key for RQ1–RQ4 across clean and 10 mutants. | Guide §8.2, §8.3; Phase 03 Step 3.1. |
| **D15** | 2026-10-19 | Implemented | Tri-modal zero-restart mutant switching via cookie (`reqverify_mutant`), header (`x-reqverify-mutant`), and fallback `MUTANT` env variable | Enables fast sub-second Playwright evaluation testing without container reboot while remaining 100% compliant with standalone Docker containers running `ENV MUTANT=Mxx`. | Guide §8.3; Phase 03 Step 3.2. |
| **D16** | 2026-10-19 | Implemented | Hardened multi-stage containerization with pinned `node:22.14-alpine`, non-root user `node` (UID 1000), and `techstore/scripts/build_mutants.ps1` for 11 immutable tags | Conforms to CIS Docker Benchmark v1.8.0, dropping root privilege, while Invariant D6 `.dockerignore` guarantees black-box isolation of mutant metadata. | CIS Docker Benchmark v1.8.0; Guide §8.3, §16.3; Phase 03 Step 3.3. |
| **D17** | 2026-10-20 | Implemented | Agent 1 prompt formulation strictly requesting a single short justification sentence in `rationale` (min_length=10) and banning chain-of-thought | Prevents Anthropic API `reasoning_extraction` refusal triggers on structured schema extraction calls. | Guide §1 Item 6, §9; Phase 04 Step 4.3. |
| **D18** | 2026-10-20 | Implemented | Four-rule code post-processing pipeline: verbatim whitespace-normalized span validation, deterministic SHA-256 IDs (`make_condition_id`), duplicate predicate filtering, and error metric tracking | Enforces ground-truth traceability and prevents hallucinated spans or duplicates from polluting downstream test generation. | Guide §7.2, §9; Phase 04 Step 4.3. |
